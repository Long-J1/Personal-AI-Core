## 二、模块职责与扩展点

| 模块 | 现在做什么 | 未来怎么扩（不推翻现有结构） |
|---|---|---|
| `perception/` | 图片归一化、摄像头抓帧 | 加 `asr.py`（麦克风→文本），事件 `source` 加新类型 |
| `models/` | `BaseModelAdapter.chat()` 单接口 | 换云端 API/本地新模型 = 新写一个 adapter；`PAI_MODEL` 环境变量切换 |
| `core/understanding.py` | JSON 抽取 + 容错解析 → Event | 提示词迭代；输出 schema 升版本（`schema_version` 字段已预留） |
| `core/policy.py` | “是否值得记忆”（阈值/暂停/保守兜底） | 接更聪明的取舍模型，接口 `should_remember` 不变 |
| `core/intervention.py` | V0.1 永远沉默（占位） | 实现任务书 §8 决策树：重要性×用户状态×打扰成本 |
| `memory/` | Event + facts 两张表，LIKE 检索 | 加 `embeddings` 表做向量检索，`search_events` 签名不变 |
| `core/context.py` | 时间词解析、5 级检索级联、带依据回答 | 查询理解可升级为 LLM 改写 |
| `agent/` | 只读记忆工具注册表 | 接 LLM tool-calling 循环 + 新工具（日历、提醒…） |
| `interfaces/` | 单页 Web UI + JSON API | API 即设备协议：眼镜/手表/手机直接消费同一套端点 |

## 三、记忆分层（对照任务书 §7）

| 层 | V0.1 实现 | 位置 |
|---|---|---|
| 事件记忆 | ✅ 每次观察一条 Event（含时间/场景/活动/物品/描述/重要度） | `events` 表 |
| 事实记忆 | ✅ 雏形：理解时提取的长期事实自动并入（去重） | `facts` 表 |
| 模式记忆 | ⬜ 留空（需多次事件归纳，V0.2+） | — |
| 关系/交互记忆 | ⬜ 留空（需要用户反馈信号） | — |

## 四、隐私设计

1. **暂停开关**：暂停后 `observe` 第一步就返回——不调用模型、不落库（有测试保证）。
2. **最小化存储**：原图不落盘，只存 ≤320px JPEG 缩略图；图片在内存中处理完即丢。
3. **用户所有权**：单条删除、清空全部、JSON 导出（含事件+事实+元信息）三个端点齐备。
4. **数据边界**：所有数据在 `data/personal_ai.db`（gitignore），服务只绑 `127.0.0.1`。

## 五、失败模式与降级

| 故障 | 行为 |
|---|---|
| Ollama 连不上/模型缺失 | `observe` 返回明确“模型错误”；`recall` 降级为直接列出检索到的记忆 |
| 模型输出不是 JSON | 保守记忆原文（`scene=（未结构化）`），不丢数据、不崩管线 |
| 数据库单行损坏 | 该行跳过并记 warning，其余照常返回 |
| 摄像头不可用 | 返回可操作的修复提示（Win11 隐私开关路径），UI 引导改用上传 |
