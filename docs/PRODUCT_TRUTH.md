## 1. 产品定义

**一个真正属于某一个人的 AI。**
不是服务所有人的通用 AI，而是随着时间与"一个人"共同生活、共同成长、逐渐形成对这个人独特理解的 Personal AI。

- **实例与主人**：每个 Personal AI 实例都有一个明确的主人，围绕这个人建立**独立、持续、不可混淆**的个人模型。这不意味着系统只能服务一个用户——意味着任何两个实例的个人理解互不混淆、不可移植。
- **存在形式**：一个在现实生活中持续存在的 **Personal Intelligence Layer**，不是被打开才工作的应用。
- **设备观**：眼镜不是产品本身，它只是 AI 长出来的第一只眼睛；耳机是耳朵和声音接口；手表是状态与身体信息的来源；PC/服务器是大脑与长期记忆。它们是**同一个 AI 的不同身体和感官**，不是不同的 AI。**先做灵魂，再做身体。**
- **它不是什么**（技术组成 ≠ 产品本身）：
  - ✗ "AI 助手 + 摄像头"
  - ✗ "AI 眼镜"
  - ✗ "聊天机器人 + 长期记忆"
  - ✗ "RAG + Agent + 多模态" 的拼装
  - ✗ "更高级的智能音箱" / 会说酷话的贾维斯

## 2. 核心循环（正式定义）

```
观察 → 理解 → 判断 → 沉默/介入 → 行动 → 用户反馈 → 修正对用户的理解 → 下一次判断
```

- **反馈是核心机制，不是附属功能。** 没有反馈回路，循环只是一台自动机，不会成长。用户反馈（采纳、纠正、无视、打断）是"对用户的理解"唯一能自我校准的信号。
- **沉默是默认产出，介入必须赚取。** 它知道，但不一定说。真正好的 Personal AI 不是知道什么都说。
- **行动的大头发生在后台**：整理信息、建立事件、关联过去与现在、判断重要程度、准备工具、维护任务状态——很多工作用户甚至不应该看见。
- **判断打的是几份分的乘积**：事件重要性 × 用户当前状态与打扰厌恶度 × 介入收益与误判代价。机械地弹出"需要帮助吗"只算了第一份分，因此是错的。
- **循环回写的是"对用户的理解"**，不只是事件记录。

---

## 3. 认识 ≠ 懂

- **认识 = 存储**：姓名、兴趣、设备、聊天记录、偏好。是数据库问题，存了就能查。
- **懂 = 对这个人的可运行、可修正的假设**：他怎么思考、怎么工作、什么时候容易卡住、什么时候不希望被打扰、什么对他重要、哪些只是短暂兴趣、哪些目标在长期持续。

**"懂"至少同时从四个维度衡量**（不能只用预测准确率概括）：

1. 对用户未来行为/需求的**预测**
2. 对用户当前状态与上下文的**判断**
3. 主动介入是否**真正产生价值**
4. 犯错后能否根据用户**反馈修正**自己

预测可以错——错了能被纠正，才是在理解一个人；只增不改的日志做不到。
**"懂"的试金石是预测与填空**：信息缺失时，它根据对这个人的模式补上缺失，而不是什么都问。

---

## 4. 价值标准

**这个 AI 的真正价值，不主要体现在"它回答得多好"，而体现在"它在用户没有开口的时候做了多少有用的事情。"**

- 回答是副产品，后台的整理、关联、判断、准备才是产品本身。
- 标志性体验："奇怪，它为什么知道我现在需要这个？"
- 贾维斯式的工作方式，而非贾维斯式的话术：一直存在、知道环境、拥有上下文、会判断、可以行动、大部分时候不打扰、需要时已经准备好。

---

## 5. 克制（产品性格）

- **产品形态**：非常安静、但始终在线的智能层。不频繁主动说话，不为表现智能而汇报，不成为耳边一直说话的机器人。
- **开发阶段**：保留"沉默记账"作为**可审计机制**——记录"观察到什么 → 判断不介入 → 理由"，用于调试与校准判断力。
- **正式产品**：**不永久保存每一次普通沉默决策**。优先保存：高价值判断、重要错误、用户反馈、会改变未来行为的经验。

## 6. 信任与用户掌控（核心属性）

**这不是普通隐私功能，是产品的核心属性。** 用户对自己的"被理解"拥有完整主权，至少能：

| 能力 | 含义 |
|---|---|
| **理解** | 看懂 AI 对自己形成了什么理解、依据是什么 |
| **纠正** | 改掉错误的理解，且纠正立即生效 |
| **删除** | 移除任何一条理解，移除后不再被使用 |
| **暂停** | 一键停止观察、记录、沉淀 |
| **限制** | 约束 AI 在哪些范围内了解自己 |

信任不是功能列表里的一项，是产品成立的前提。

## 7. 记忆与上下文的构成

目标是 **Personal Memory + Personal Context + User Model**，
不是聊天记录数据库，也不是单纯的 RAG。

需要区分的至少包括：
1. 事实记忆　2. 事件记忆　3. 长期模式　4. 用户偏好
5. 用户长期目标　6. 用户与 AI 的互动习惯　7. AI 对当前用户的动态理解

组织为三条流水线（不是七张表）：

- **经历层**：事件 + 事实 —— 发生过什么
- **编译层**：模式 / 偏好 / 长期目标 —— 从经历中压缩出"你是谁"
- **关系层与现在时**：互动习惯 + 动态理解 —— 怎么与他相处、他此刻状态如何

**记忆必须是有损的**：不是所有事情都值得永久记住。它要学会什么应该记住、什么只短期保存、什么值得总结、什么可以忘掉。**"该记住什么"本身就是理解的一部分。**

## 8. 功能过滤器（日常决策工具）

任何新功能 / 架构 / UI / Agent 能力，逐条过筛：

1. 它改善了**观察**吗？
2. 它改善了**对这个人的理解**吗？
3. 它改善了**判断**吗？
4. 它改善了**准备**（未被请求时的就绪度）吗？
5. 它改善了**反馈学习**或**信任/掌控**吗？

**全部为否 → 排后或不做。**
暂时不需要的架构，不为了"完整"提前实现；不为炫技加入只增功能不增理解的东西。

---

## 9. 第一版的证明义务

第一版必须非常小，但必须证明一件事：

> **AI 能不能开始"拥有这个人的上下文"。**

即：感知 → 理解 → 形成事件 → 判断是否值得记住 → 保存 → 检索 → 回忆 → **利用过去理解现在**。

先证明这个闭环成立，之后再依次加入：语音、持续视觉、用户模型、主动判断、工具调用、自动行动、多设备、AR——最终才走向真正的"AI 眼睛"。
