## 一、V0.2 唯一要证明的命题

> **AI 能不能开始"拥有这个人的上下文"。**

V0.1 证明了管道通，但它有**档案库**、没有**上下文**：记忆只在被提问时才被读取，
互动不回写，"利用过去理解现在"只有半环。V0.2 补齐这半环。

具体到可操作定义：

1. **Personal Context 成为一等对象**——结构化存在、可被查看、来自真实交互
2. **每次交互先读后写**——读上下文组装当前状态，交互后把新理解沉淀回去
3. **能利用过去理解现在**——重提旧事，主动接回上次的进展与卡点
4. **反馈能修正理解**——用户说"不对"，理解会改，且改了立即生效
5. **信任与掌控覆盖上下文**——看得懂、能纠正、能删除、能暂停、能导出

## 三、验收标准

每条通过标准都必须**可实测**（自动化测试 / 演示脚本 / 明确人工步骤），
且每条标注它增强了北极星问题里的哪个维度。

### A 组：上下文成立与信任掌控

| # | 验收项 | 通过标准 | 增强 |
|---|---|---|---|
| A1 | 上下文可看懂 | UI/API 能列出"AI 对你的理解"（画像条目、事实、当前动态），每条带来源与时间；内容来自真实交互而非手工填充 | 信任·理解 |
| A2 | 读写闭环 | 自动化测试断言：每轮交互发生**上下文读取**，交互结束产生**沉淀写入** | Personal Context |
| A3 | 纠正生效 | 用户发出纠正（如"不对，我是高二不是高三"）→ 对应条目更新或标记 → 历史可查 → **同一会话后续回答即使用修正值** | 反馈·修正 |
| A4 | 删除即失效 | 删除任一理解条目 → 后续交互不再引用它（自动化测试断言） | 信任·掌控 |
| A5 | 暂停有效 | 暂停后不观察、不沉淀，状态醒目、可逆（自动化测试断言） | 信任·掌控 |

### B 组：利用过去理解现在

| # | 验收项 | 通过标准 | 增强 |
|---|---|---|---|
| B1 | 接回旧事 | 演示场景：几天前记录了项目 X 的进展与卡点 → 再次提起 X → **问题本身不含存储时的关键词**，AI 仍主动带出"上次做到哪 / 卡在哪 / 当时为什么停" | 利用理解·准备 |
| B2 | 跨轮连贯 | 三轮之前透露的约束或信息，在后续回答中自然适用，无需用户重复 | Personal Context |
| B3 | 无问先备 | 交互开始时上下文已组装完毕（近期事件 + 画像 + 动态），日志可证；用户不必重新交代背景 | 准备 |

### C 组：克制与后台（开发阶段形态）

| # | 验收项 | 通过标准 | 增强 |
|---|---|---|---|
| C1 | 沉默可审计 | 开发日志记录"观察 → 判断不介入 → 理由"；**测试断言这些记录不进入正式记忆库**（不永久保存普通沉默） | 克制（开发期） |
| C2 | 后台不打扰 | 沉淀在后台静默完成，无弹窗、无"我学到了 XX"式汇报（人工验收 + 代码路径检查） | 沉默·后台 |

### D 组：回归与底线

| # | 验收项 | 通过标准 | 增强 |
|---|---|---|---|
| D1 | V0.1 回归 | 原有 72 个测试全部保持通过（闭环不被破坏） | 可靠地利用理解 |
| D2 | 过滤器留痕 | 本版每个功能在提交前过了一遍功能过滤器，被拒绝的候选项记录在案（防止蔓延） | 纪律 |
