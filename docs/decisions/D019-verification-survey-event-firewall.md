# D019 — V0.5.4 验证链调查与 Event 防火墙（设计决策）

日期：2026-09-30 ｜ 状态：**已实施**（event 防火墙部分；
验证链调查结论保留为 V0.5.5 重设计任务，本版不动机制）

## 背景

V0.5.3 复测通过两个 P0，信任地基成立。V0.5.4 只做两件：
验证链零触发调查（只报告不动手）+ event 防火墙（小改）。
假设生命周期暂缓（等调查结论再定假设的去留）。

## 决策

1. **调查先于动手**：8 天 0 触发不能直接归因于"门槛高"，
   真实数据逐条过筛后是 E（多因共存，主因是产品假设与聊天节奏不合）。
   没做这步就调阈值，等于给垃圾标签开骚扰许可证。
2. **换主链而非调参数**：自然确认（deposit correct）已经在正确落链，
   结构化提问 8 天 0 触发。主链应该是前者，提问降级为兜底。
   这个判断留 V0.5.5，本版只记录。
3. **event 防火墙承认"分量"与"真假"是两回事**：
   用户亲口说的鸡腿，来源分类拦不住它——硬拦等于撒谎（用户确实说了）。
   所以闲聊只做 importance 低价值标记（0.2），不做拒绝：
   记还是要记（诚实），分量要轻（价值判断）。二值"记/不记"是 context 的语言，
   event 说分量。用户拍板，D019 记录。
4. **event 不做纠正联动**：无 status 列就不联动，加列是 scope creep。
   存量鸡腿不动，只管入口。诚实比彻底重要。
5. **感知通道分开治理**：摄像头事件和对话事件来源不同，
   统一 firewall 指"对话沉淀入口统一"，不是全库统一。注释写清边界。

## 被拒绝的候选项

- 直接调低 CONFIRM_BAND/冷却（垃圾标签会骚扰用户；调查结论不允许）。
- 删除验证机制（8 天样本 + 验收链全绿，机制本身是对的，
  错的是主次关系；砍是懒政）。
- event 加 status 列做联动（扩大回归面；V0.5.5 议）。
- 清理库里鸡腿 event（动历史数据；入口管住就行）。
- 假设生命周期（过期/合并/清理；等调查结论，本版不碰）。
