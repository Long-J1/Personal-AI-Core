# D016 — V0.5.1 可靠性：规则兜底优先于模型输出

日期：2026-09-30 ｜ 状态：已实施

## 背景

V0.5 产品审计（真机）证明：deposit JSON 解析失败一次，用户明确的"不对"
就被静默吞掉，同一回答继续用着被否认的假设。单测全用合法 Mock JSON，
所以从没暴露。教训：**凡是信任相关的链路，必须有一条不经过模型的规则路径。**

## 决策

1. **纠正走双通道**：模型提取（主）+ 关键词直连（备）。备通道触发条件
   收紧到"显式否决词 + 本轮零纠正"，误伤面可控；触发与否认全记日志。
2. **提问设门**：疑问 + 无依据 → 只读不写。有依据的提问（"最近状态怎么样"）
   与陈述句行为不变——用交集判据而非问题类型一刀切。
3. **合并加数字守卫**：数字不同即不同事实。阈值 0.6 保持不动（复述合并
   仍需要），只堵"不同"误判，不碰"相同"召回。
4. **每日配额方案否决**：数字拍脑袋，且会误伤 acceptance 的合法播种
   （6 条/轮），不如语义门精确。记录在案，不再提。

## 被拒绝的候选项

- deposit 失败重试模型（烧钱且治标；规则路径零成本）。
- 否决词模糊匹配/语义分类（中文否定太绕；关键词 + 可观测日志够用）。
- 合并阈值上调到 0.85（治标，数字对例 0.78 照样合并；守卫釜底抽薪）。
- 为兜底新增"否决专用表"（record_correction_hit 复用足够，不添表）。
