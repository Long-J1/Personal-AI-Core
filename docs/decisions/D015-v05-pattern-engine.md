# D015 — V0.5 Pattern Engine 设计（从记忆到成长）

日期：2026-09-29 ｜ 状态：设计中（未开工，对应 `docs/PLAN_v0.5.md`）

## 背景

V0.4 审计证明：系统会"记住用户"（Context/假设/验证闭环真机成立），
但能力停在"记忆增强聊天机器人"。R2 审计还暴露：真实数据下只能长出
一个 interaction 假设（巨组合并），验证功能无触发机会。
V0.5 先修漏斗（P0/P1/P2），再建晋升链（Pattern），最后给方向（Goal + Reflection）。

## 决策

1. **Pattern 是"验证过的规律"，不是"高级人格"**：第一阶段只证明"发现稳定模式
   并改变理解"，不追求数量；一条端到端即达标。
2. **双来源，但都有证据**：A（confirmed 假设晋升，证据=假设 id 链）、
   B（用户明确表达 + 走一次验证问题，证据=原话 + 引用行）。
   B 不许跳过验证——"亲口说"不等于"免检"。
3. **confirmed 才进 prompt**：规律门槛高于猜测；tentative 只活在 UI。
4. **Goal 只能人给**：创建函数签名只收用户原话；模型生成文本调创建必须拒绝
   （单测锁死）。AI 只做关联展示，不做目标推理。
5. **Reflection 是纯函数**：`build_weekly_digest` 无模型调用、无后台；
   触发只在用户主动打开时；失败静默。
6. **P2 选"去计数"不选"刷新"**：文本永不过期 > 写操作变多 + 日志灌水；
   存量历史原样（不重写过去）。

## 被拒绝的候选项

- Embedding / RAG / 向量库做主题分裂（P0 纯规则可解，不引入重依赖）
- LLM 生成 Pattern/画像/问题（不可测，违反 D007 精神）
- 后台 Reflection 进程/定时器/推送（V0.6 议题，本版 grep 锁死）
- 一次聊天直出 Pattern（违反晋升铁律；B 路径的验证问题就是为此设的）
- AI 推测人生目标（红线；Goal 创建只收用户原话）
- Pattern 自动行动/干预（V0.5 只到"引用"，行动是 V0.6）
- UI 大改（除 Reflection 只读卡片；Pattern/Goal 复用假设区块展示范式）
- R2 语义聚类/LLM 关键词（字面规则 + 停用表够用，审计数据即回归夹具）
- confirmed 假设自动转 Pattern（必须经晋升规则计数，确认≠规律）

## 风险与诚实声明

- Pattern 稀疏是设计不是 bug；上线后长期为空是预期。
- Goal 本版只引用不理解；"AI 懂你的目标"要等 V0.6 判断层，
  修订 PRODUCT_TRUTH 时写明，防自嗨。

## 实现期追加决策（H4 回归暴露的两个真问题）

- **改述复活**：纠正改写条目内容 → R2 重打标签 → scope 精确去重 miss →
  建出双胞胎。修：`support_coverage()` 单查询 + 成员重叠去重
  （按 id 认，不按文字认）；覆盖对象 rejected 则尊重否决不复活。
- **僵尸问题**：本轮问出的问题若同轮被沉淀纠正联动解决，
  挂起不清会污染下轮。修：写路径收尾复核目标状态，
  非 tentative/proposed 即收回挂起 + 元数据置空（回答正文已发出，保留原文）。
- **B-scope 标签过严**：整串长词作标签导致相关性太严。
  修：取首关键词首个二连字（召回优先，冷却/次数/否决兜底）。
