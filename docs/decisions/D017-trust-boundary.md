# D017 — V0.5.2 Trust Boundary（信任边界）设计决策

日期：2026-09-30 ｜ 状态：**已实施**（commit 见 git log V0.5.2；
对应 `docs/PLAN_v0.5.2.md`，测试 `tests/test_trust_boundary.py` 24 项 +
`scripts/acceptance_v051.py` 12 步 + 全量回归 295 通过）

## 背景

V0.5.1 真实 32 轮审计 + V0.5 产品级验证任务证明：系统"记得"的能力成立，
但信任链三处断裂——幻觉入库（指数函数/9月30日）、纠正不断根（函数条目永 active）、
"别记"反成记忆；另有 R2 引号 scope 致 13 轮零提问、记忆无质量等级。
V0.5.2 不加能力，只修"敢不敢信"。

## 决策

1. **来源标记前移**：不在模型输出里加字段（模型不可信），而在写入时用规则分类。
   `user_direct` 判定用"归一化包含或 bigram 交集"，阈值写死可测。
2. **推测禁入 memory，只能进 hypothesis**：宁可假设池多几条待验证，
   不让推测穿上事实的外衣。这是"事实与假设物理隔离"（V0.3 铁律）向写入侧的延伸。
3. **纠正不断根靠状态列，不靠删除**：`outdated`/`rejected` + 原因保留，
   prompt 只读 active。删除是物理消失，状态是可审计的历史——信任产品选后者。
4. **"别记"是硬开关不是意图识别**：关键词命中即整轮跳过全部写路径，
   不让模型"决定"记不记。诚实回答靠本轮 prompt 注入保证下限。
5. **标签清洗 + 相关性改 bigram 交集**：子串匹配在 P0 长标签下已死，
   与其缩短标签，不如放宽匹配——两边同时修，单测各锁一边。
6. **质量分只做排序，不做展示**：prompt 文本零 churn，避免 UI/测试连锁；
   行为变化只来自顺序。展示是 V0.6 议题。
7. **老数据一律按低可信回填**：无法区分的一律 `inferred`/0.5，只有用户亲手写的
   （manual/correction）才给 0.95。诚实比好看重要。
8. **有据复述单列 `db_grounded`（实施期追加）**：防火墙上线后，
   V0.5.1 的"有依据提问照常沉淀"保证被误伤（"CSP备考顺利"无用户原话可对，
   差点被扔进假设池）。`db_grounded` = 既有理解/事件里有据可查的复述，
   进 memory 但置信 0.8——既不冒充 `user_direct`，也不把有据的东西当推测。
9. **复述阈值按 kind 分档（实施期追加，两次校准）**：归一化包含之外，
   二连字 overlap 系数 interaction 取宽松线（共享≥1 且 ≥0.2），其余取严格线
   （共享≥2 且 ≥0.4）。第一次校准是 D007 场景（共享 4/16=0.25）；
   第二次是 v04 回归逼出来的——"回答简短些"只跟"以后说话简短点"共享"简短"
   一个二连字，统一≥2 会把 v04 第二主题提问链掐死。interaction 先验更高
   （本就是用户对 AI 的要求），误判成本也低于 fact，值得放宽。

## 被拒绝的候选项

- 用 LLM 做来源分类（自己当自己的裁判；规则可测性优先）。
- 纠正=删除旧条目（丢历史，违信任审计；状态列是深思熟虑后的选择）。
- "别记"走意图分类模型（杀鸡用牛刀；关键词表 + 单测锁死足够，
  漏网之鱼靠"失败 admission"：没命中的"别记"表达方式进附录，下版补）。
- R2 改 embedding 聚类（红线；bigram 交集已够用，审计数据即回归夹具）。
- 质量分展示在 UI（华而不实；排序先行，展示后议）。
- deposit 失败重试模型（烧钱且治标；V0.5.1 已否决，本次重申）。
- Test5 用真实模型断言"谦虚措辞"（不可测；只断言指令注入 + Mock 固定回答）。
