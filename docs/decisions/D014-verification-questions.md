# D014 — V0.4 验证提问设计（搭便车，不拦路）

日期：2026-09-29 ｜ 状态：已实施（`docs/PLAN_v0.4.md`）

## 决策

1. **问题只搭便车**：用户主动发起的对话轮次里附带一句；无推送/定时/后台。
   触发点在 `conversation.chat` 请求路径内（用户动作的同步上下文），
   不新增任何调度设施（acceptance 用 grep 断言锁死）。
2. **先解决再组装**：挂起回答的分类/落链发生在 prompt 组装之前，
   确认当轮即用上（行为变化可断言在同一轮）。
3. **确认 ≠ 统计证据**：`record_verification_confirm` 只改状态不清零统计，
   confidence 不动（沿用 V0.3"确认≠高置信度"），但回答作为 support 证据入链
   （support_count+1，用户 verdict 可追溯）。
4. **分类否决优先**：先判否决再判确认（防"不对"误命中"对"）；
   确认词表保守（"嗯/好/对"一律回避，宁可漏判）。
5. **挂起是单例行状态**：`pending_question` 存假设行上（重启不丢），
   全局只挂一个；任何渠道的解决（对话/UI/删除）都清 pending。
6. **沉淀吃模型原文**：附带的问题文本不进 deposit（问不算答），
   历史存用户实际看到的版本。
7. **否决过的主题不再打扰**：inducer 跳过 rejected scope（V0.3 语义的自然延伸）。

## 被拒绝的候选项

- LLM 生成问题文本（措辞不可测，违反 D007 精神）
- 一轮多问 / 追问 / 问 confirmed 假设（存在感超标，V0.5 再议）
- UI 新区块（问题文本自带来源说明；过度 UI = 高存在感，违背低打扰）
- 语义相关性（embedding/向量；子串保守匹配够用且可测）
- pending 按 session 存（跨会话先答旧问题是合法自然窗口，按行存更简单）
- 确认联动提置信度（破坏"确认≠置信"分离；支持计数照常+1 已足够追溯）
- "嗯/好"算确认（歧义太大；判回避+冷却是最安全的默认）
