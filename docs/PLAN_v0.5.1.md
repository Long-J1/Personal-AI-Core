# V0.5.1 可靠性补丁 — 让已有的系统值得信任

> 地位：V0.5 的修复分支，不新增任何能力（无新表/新端点/新 UI/新模型调用）。
> 起因：V0.5 产品级验证审计（2026-09-30，真机）的三项实锤。
> 状态：**已完成**

## 修了什么（3 项）

1. **规则兜底纠正链**（`core/deposit.py`）：显式否决 + 本轮无纠正生效 →
   按关键词直连本轮理解做反证，不依赖模型 JSON。已有纠正时不重复处罚；
   无关联时记 warning 可观测。
2. **无依据提问门**（同上）：问句 + 与现有理解/近期事件零交集 →
   本轮只处理纠正，不新建理解/事件。有依据的提问与陈述句不受影响。
3. **数字守卫**（`memory/context_store.py`）：数字序列不同直接相似度 0
  （1号/2号、三天/五天不再合并）；纯复述照常合并。

## 回归证明

- `tests/test_reliability.py` 6 项：垃圾 JSON 否认生效 / 不重复处罚 /
  无依据零新建但纠正照常 / 有依据与陈述正常 / 无关联否决不崩 /
  数字不合并 + 复述合并。
- 全量 271 测试通过；acceptance_v03/v04/v05 全过。

## 已知残留（诚实记录，非本次范围）

- 否决词误判（如"不对吗"作疑问）只记日志不处理，靠"无关联即跳过"兜住。
- 中文数字只覆盖常用字（兆/亿未列），极罕见。
- deposit 失败的本轮仍可能沉淀出噪音条目（门只拦新建，模型输出的
  corrections 为空时无东西可拦——这是对的：失败路径本来就没写入）。
